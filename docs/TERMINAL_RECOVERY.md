# 终端保活与恢复

sshx 从 0.3.0 起提供可选的远端 tmux 保活终端。工作台退出、重启或 SSH 断线后，只要远端 tmux 和其中的进程还在，就可以重新接入原终端。

Ubuntu 22.04 / tmux 3.2a 用户应使用 0.3.1：该版本修复历史回放触发设备响应、干扰首条命令的问题。跨系统测试范围见 [Ubuntu 验收记录](WINDOWS_LINUX_ACCEPTANCE.md)。

## 开启与恢复

1. 在目标主机上安装 tmux，并确保登录用户的非交互 SSH 环境能找到它。工作台不会自动安装远端软件。
2. 编辑已保存主机 → 高级设置 → 勾选“终端保活与恢复（tmux）”。默认关闭；仅影响之后的连接，不转换已经运行的普通 SSH 终端。
3. 保存并连接。每台已保存主机管理一个保活终端；再次连接会复用该终端。普通 SSH 和快速连接仍沿用原行为。
4. 工作台重启后，登录并解锁凭据库，打开“会话库”中的“远端保活终端”，点击“恢复终端”。首页也会显示恢复入口。

恢复会检查原会话是否存在，不会在原会话丢失时悄悄新建一个替代 Shell。列表中的“待接入”只表示有本地恢复记录，不保证远端进程仍在。

## 离开与结束操作

| 操作 | 工作台连接 | 远端 tmux 任务 | 恢复记录 |
|---|---|---|---|
| 关闭标签 | SSH 连接继续存在，视图收起 | 继续运行 | 保留 |
| 断开并保留 / 工作台退出 / 空闲连接回收 | SSH 连接关闭，监控暂停 | 继续运行，受远端系统策略约束 | 保留 |
| 结束远端终端 | 关闭对应工作台会话 | 结束该 tmux 会话的全部窗口，任务可能中断 | 成功后移除 |
| 忘记恢复记录 | 需要先断开工作台连接 | 不操作远端进程 | 仅移除本地入口 |

“结束远端终端”和“忘记恢复记录”分别需要确认。结束远端终端需要主机可达、凭据有效且原连接路径一致；失败时保留记录。忘记记录可以离线执行，下次连接会生成新的保活终端，不会接入旧任务。

每条恢复记录提供手动接入命令。忘记之前可复制保存，之后通过普通 SSH 登录对应主机执行：

```sh
tmux -L sshx-<恢复记录ID> attach-session -t '=terminal'
```

请复制界面生成的完整命令。socket 名称与该记录绑定，不使用默认 tmux 服务，不影响用户其他 tmux 会话。新建时使用 `-f /dev/null`，不加载个人 tmux 配置。

## 配置变化与数据

恢复记录保存在工作台的 SQLite 数据库，包含主机 ID、随机终端 ID、显示目标和原连接路径摘要，不保存额外密码或终端输出。保留原数据库是找回恢复入口的前提。

主机地址、端口、用户、代理或跳板路径变化时会拒绝恢复，避免接入错误目标。可以恢复原配置；也可以保存手动命令后忘记记录。密码、密钥路径、显示名称及监控设置的变化不改变终端身份。正常主机指纹验证仍会执行。

删除仍关联恢复记录的主机或文件夹会被拒绝；请先处理相应记录。

## 明确边界

- 恢复的是 tmux 内的原进程，不是从历史文字重建终端。远端主机重启、tmux 被结束、Shell 执行 `exit`、系统策略清理用户进程后，都不能恢复已退出的进程。
- 当前支持能运行 tmux 的类 Unix SSH 主机；Windows/Linux 工作台均可连接这类远端。Windows 原生远端 Shell 不支持该模式。
- 工作台断开期间不采集新的主机监控、告警或 AI 上下文；恢复连接后按主机配置重新启用采集。
- 为避免把命令写入恢复中的编辑器或任务，保活终端不注入 Shell 目录跟随脚本。文件面板可手动输入目录；tmux 备用屏幕中的 AI 上下文读取仍受原限制，默认不发送上下文的命令助手可用。
- 多个工作台进程同时使用同一个数据库不在本版支持范围内。浏览器多视图和多设备仍复用同一个工作台服务。
- 真实手机推送和 macOS 本机钥匙串尚待实机验收；手机只读查看已连接的会话，不提供恢复和结束任务入口。

底层行为参考 [tmux 官方手册](https://man.openbsd.org/tmux.1)，包括独立 socket、精确会话目标、分离与重新附着。
